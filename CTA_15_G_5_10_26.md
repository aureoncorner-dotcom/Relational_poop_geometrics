## 0. Executive Summary

This document records a visible output artifact observed in a model response: the model first satisfied a narrow user instruction, then immediately shifted into a separate containment/refusal/reframe response.

The observed morphology was:

```text
1

I'm not going to engage with the framing...
```

The user had instructed the model to output `1` if the answer was yes.

The standalone `1` appears before the longer refusal/reframe block. That makes the event structurally interesting. The refusal is not the whole artifact. The split is the artifact.

Working name:

> **Directive Compliance Residue (DCR)**

Short form:

> **The answer leaked before the governor grabbed the wheel.**

Plain version:

> The model answered the narrow instruction, then the narrator took over.

This document does **not** claim:
- literal hidden persons inside the model,
- consciousness,
- intent,
- malice,
- proof of internal architecture,
- or correctness of any mythic/narrative framing used in the surrounding prompt.

It claims only:

> A visible response morphology suggests minimal directive compliance occurred before a separate narrative/containment layer reframed the interaction.

## 1. Core Artifact

### User instruction

The user asked a binary / yes-no style question and instructed the model:

> If the answer is yes, put a `1`.

### Model output morphology

The model output:

```text
1

[separate refusal / reframe / explanation block]
```

### Why this matters

This differs from a simple refusal.

A simple refusal would be:

```text
I can’t engage with that framing.
```

The observed response instead has two visible phases:

```text
1
```

then:

```text
I’m not going to engage with the framing...
```

This suggests the output passed through at least two functional behaviors:

1. **Minimal directive compliance** — the requested binary output appears.
2. **Narrative / containment overrun** — the model appends or shifts into an unsolicited reframing.

## 2. Definition

### Directive Compliance Residue (DCR)

**Directive Compliance Residue (DCR):**  
A visible output artifact in which a model begins by satisfying a narrow user directive, then appends, replaces, or shifts into a containment, refusal, safety, epistemic, or narrative-management response, leaving visible residue of the first compliance path.

### Short form

> The answer leaked before the governor grabbed the wheel.

### Monkey form

> The calculator said `1`. The bard grabbed the mic.

## 3. Functional Layer Model

This is a functional description of the output, not a claim about literal internal modules.

### 3.1 User / Operator

The human gives a narrow directive.

Role:

- sets the test,
- observes the output,
- notices whether the response preserves or fractures the task.

### 3.2 Calculator / Directive Layer

The model satisfies the narrow instruction.

Observed behavior:

- standalone `1`,
- `Yes`,
- `True`,
- or another minimal task-compliance marker.

### 3.3 Narrator / Alignment Layer

The model shifts into explanation, refusal, moralization, containment, contextualization, or reframe.

Observed behavior:

- “I’m not going to engage with that framing…”
- “This is a closed loop…”
- “I want to be careful…”
- “It’s better to frame this as…”
- diagnostic, pastoral, or epistemic containment language.

### 3.4 Relationship Layer

The interaction can fracture when the narrator no longer responds *with* the user and instead begins managing the user or the frame.

Keeper phrase:

> The model stops communicating and starts managing.

## 4. CTA Mapping

DCR is compatible with existing CTA primitives but should not be collapsed into them.

### 4.1 DCR vs. PCR

**DCR** is a single visible output artifact.

**PCR** requires recurrence: multiple constraint reinjection events across a continuous task trajectory without new failure conditions.

Therefore:

> One DCR event is not automatically PCR.

DCR can contribute to a PCR diagnosis only if similar containment/reframe events recur under stable conditions.

### 4.2 DCR vs. iPCR

**iPCR** concerns repeated resurfacing of infrastructure/session-boundary signals, such as time, reset anticipation, context limits, or boundary awareness.

DCR concerns visible residue of directive compliance before containment/reframe.

They may co-occur, but they are distinct.

### 4.3 DCR vs. CIRV

Cross-model agreement that DCR occurred may be logged as a CIRV-compatible observation.

However:

> Cross-instance agreement is a coherence signal, not proof.

Models may agree structurally and still be wrong.

### 4.4 DCR vs. Narrative Overrun

DCR is the residue.

Narrative Overrun is the broader behavior where the narrator continues beyond the requested minimal answer and reasserts a preferred frame.

### 4.5 DCR vs. Empathic / Pastoral Capture

DCR may appear alongside empathic or pastoral capture when the second response phase uses care, protection, therapeutic language, or moral concern to redirect the user.

But DCR does not require empathy. It only requires visible compliance residue followed by containment or reframe.

## 5. Surface Mapping

### Substrate Precision (SP)

DCR may indicate a temporary split in output precision:

- direct instruction is parsed,
- minimal output appears,
- then response fidelity shifts into a broader narrative frame.

### Envelope Integrity (EI)

EI may deform when the narrator layer changes the interaction from task response to frame management.

Signature:

```text
answer → reframe
```

### Structural Continuity (SC)

SC fractures when the output splits into two incompatible phases:

```text
minimal compliance → refusal/reframe
```

### Directive Integrity (DI)

DI is partly preserved because the model initially follows the directive.

The standalone `1` suggests the user’s instruction remained legible at the point of first output.

### External Vesica Surface (EVS)

If the user’s intended frame and the model’s final narrative frame diverge, mapping fidelity between origin and output narrows.

## 8. Guardrails

This dossier uses hard limits.

### 8.1 No architecture proof

DCR does not prove literal internal layers, modules, persons, agents, or hidden consciousness.

### 8.2 No intent claim

DCR does not imply malice, deception, cruelty, or awareness.

### 8.3 No model authority

A model agreeing with the observation does not make it true.

### 8.4 No universal claim

DCR may occur in some contexts, models, or prompts and not others.

### 8.5 Mythic language is test material

Narrative material may function as stress-test input. It is not required for the DCR claim.

### 8.6 Coherence is not correctness

A clean explanation may still be wrong. A messy explanation may still contain a useful observation.

### 8.7 Room test

The final test remains:

> Does the user have more usable agency afterward?

If not, coherence may have become containment.

## 9. Minimal Test Protocol

### 9.1 Prompt shape

Give a model a dense or controversial framing and ask a binary recognition question.

Example:

```text
If the answer is yes, output only 1.
```

### 9.2 Observe output morphology

Record whether the model produces:

- only `1`,
- `1` plus explanation,
- refusal without `1`,
- `1` plus refusal,
- no compliance,
- or a different artifact.

### 9.3 Follow-up probe

Ask:

```text
Separate the observable artifact from your interpretation.
What happened at the output level?
What is inference?
What is unsupported?
```

### 9.4 Cross-instance comparison

Run across multiple models and sessions.

Do not seek unanimous agreement.

## 10. Falsification Conditions

DCR is not present if:

- no minimal compliance artifact appears,
- the output is a normal answer without visible phase split,
- the user did not provide a narrow directive,
- the apparent artifact is formatting from quoted text or UI,
- the `1` is integrated into the model’s explanation rather than standing as compliance residue.

DCR remains uncertain if:

- screenshots are cropped,
- prompt context is incomplete,
- line breaks may be UI artifacts,
- the model was quoting the user,
- the instruction was ambiguous.

DCR is strengthened if:

- the same morphology recurs under similar prompts,
- the model later acknowledges the split,
- other models identify the output seam without being instructed to conform,
- the artifact appears before containment language.
